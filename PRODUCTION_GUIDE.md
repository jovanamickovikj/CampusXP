# CampusXP — Production Migration Guide

This guide explains exactly how to move CampusXP from the H2 in-memory database
used during development to a real PostgreSQL database suitable for production.

---

## Current State (Development)

| Thing           | Value                             |
|-----------------|-----------------------------------|
| Database        | H2 in-memory (wiped on restart)   |
| Schema          | Auto-generated by Hibernate       |
| Seed data       | `DataInitializer.java` (runs once)|
| File uploads    | `uploads/` folder (local disk)    |
| Active profile  | `dev`                             |

---

## Step 1 — Install PostgreSQL

**Windows:**
1. Download the installer from https://www.postgresql.org/download/windows/
2. Run the installer. Choose a port (default **5432** is fine).
3. Set a password for the `postgres` superuser. Remember it.
4. After install, open **pgAdmin** or use the `psql` shell.

**Linux (Ubuntu/Debian):**
```bash
sudo apt install postgresql postgresql-contrib
sudo systemctl start postgresql
sudo systemctl enable postgresql
```

**macOS (Homebrew):**
```bash
brew install postgresql@16
brew services start postgresql@16
```

---

## Step 2 — Create the Database and User

Open a `psql` shell as the `postgres` superuser:

```sql
-- Create a dedicated database user (don't run your app as postgres superuser)
CREATE USER campusxp WITH PASSWORD 'choose-a-strong-password-here';

-- Create the database owned by that user
CREATE DATABASE campusxp OWNER campusxp;

-- Grant all privileges
GRANT ALL PRIVILEGES ON DATABASE campusxp TO campusxp;
```

Test the connection:
```bash
psql -h localhost -U campusxp -d campusxp
# Enter your password when prompted
```

## Step 3 — Configure the Application

Set environment variables before starting the app (never put production passwords in files):

**Windows (PowerShell):**
```powershell
$env:DB_URL      = "jdbc:postgresql://localhost:5432/campusxp"
$env:DB_USERNAME = "campusxp"
$env:DB_PASSWORD = "choose-a-strong-password-here"
```

**Linux / macOS (bash):**
```bash
export DB_URL="jdbc:postgresql://localhost:5432/campusxp"
export DB_USERNAME="campusxp"
export DB_PASSWORD="choose-a-strong-password-here"
```

Then run the app with the `prod` profile:
```bash
$env:JAVA_HOME = "C:\Program Files\Java\jdk-21"
.\mvnw spring-boot:run -Dspring-boot.run.profiles=prod
```

Or as a JAR (after `mvn package`):
```bash
java -jar target/campusxp-0.0.1-SNAPSHOT.jar --spring.profiles.active=prod
```

## Step 4 — Run Flyway Migrations

When the `prod` profile is active, Flyway automatically runs on startup.
It reads `src/main/resources/db/migration/V1__init.sql` and creates all tables.

You'll see output like:
```
Flyway Community Edition ... by Redgate
Database: jdbc:postgresql://localhost:5432/campusxp (PostgreSQL 16.x)
Successfully validated 1 migration (execution time 00:00.012s)
Current version of schema "public": << Empty Schema >>
Migrating schema "public" to version 1 - init
Successfully applied 1 migration (execution time 00:00.089s)
```

**Adding future schema changes:**
Never edit `V1__init.sql`. Instead, create a new file:
- `V2__add_notifications_table.sql`
- `V3__add_post_likes.sql`

Flyway runs each version exactly once, in order, and tracks them in `flyway_schema_history`.

## Step 5 — Seed Demo Data (Optional for Production)

The `DataInitializer.java` only runs on the `dev` profile (it's guarded by `userRepository.count() > 0`).
For production you have two options:

**Option A — Leave the database empty** (users self-register — recommended for real deployment).

**Option B — Run a one-time SQL seed script** manually:
```bash
psql -h localhost -U campusxp -d campusxp -f seed_data.sql
```

You would write `seed_data.sql` with INSERT statements for any initial admin accounts.

## Step 6 — File Storage for Uploads

### Development (current)
Files are saved to `uploads/` inside the project directory.
This works fine locally but has two problems in production:
- Files are lost if the server is restarted with a different working directory.
- Won't work if you scale to multiple server instances.

### Production Option A — Absolute local path
In `application-prod.properties`, set an absolute path:
```properties
file.upload-dir=/var/campusxp/uploads
```
Create and permission the directory:
```bash
sudo mkdir -p /var/campusxp/uploads
sudo chown campusxp:campusxp /var/campusxp/uploads
```
Files survive restarts as long as the server doesn't change. Suitable for single-server setups.

### Production Option B — Cloud Storage (recommended for scale)
Replace `FileStorageService` with an AWS S3 / Cloudflare R2 / MinIO implementation.

Add the AWS SDK dependency:
```xml
<dependency>
    <groupId>software.amazon.awssdk</groupId>
    <artifactId>s3</artifactId>
    <version>2.25.0</version>
</dependency>
```

Then rewrite `FileStorageService.store()` to upload to S3 and return the public CDN URL.
This is the correct approach for any production system with more than one user.

## Step 7 — Security Hardening Before Go-Live

### 7.1 — Change the JWT Secret
In production, the JWT secret must be a truly random 256-bit value, **not** the placeholder in `application.properties`.
```bash
# Generate a secret
openssl rand -base64 32
```
Set it as an environment variable:
```bash
export JWT_SECRET="the-random-value-you-generated"
```
Update `application.properties`:
```properties
jwt.secret=${JWT_SECRET}
```

### 7.2 — Use HTTPS
Never run a JWT-authenticated app over plain HTTP in production.
Use a reverse proxy (nginx or Caddy) to terminate TLS:
```nginx
server {
    listen 443 ssl;
    server_name campusxp.yourdomain.com;
    ssl_certificate     /etc/letsencrypt/live/campusxp.yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/campusxp.yourdomain.com/privkey.pem;

    location / {
        proxy_pass http://localhost:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```
Get a free TLS certificate with Certbot: https://certbot.eff.org

### 7.3 — Restrict Database Access
- PostgreSQL should **not** be publicly accessible. Bind it to `localhost` only.
- In `pg_hba.conf`, restrict connections to local or VPN addresses.
- Never use the `postgres` superuser for the application.

### 7.4 — Disable H2 Console
Already disabled in `application-prod.properties` (`spring.h2.console.enabled=false`).

### 7.5 — Remove `show-sql=true`
Already disabled in prod profile. SQL logs expose your schema.

## Step 8 — Backups

### Manual backup (PostgreSQL dump):
```bash
pg_dump -U campusxp -h localhost campusxp > backup_$(date +%Y%m%d).sql
```

### Restore:
```bash
psql -U campusxp -h localhost campusxp < backup_20261001.sql
```

### Automated backups (Linux cron):
```bash
# Run every day at 2 AM
crontab -e
# Add:
0 2 * * * pg_dump -U campusxp campusxp | gzip > /backups/campusxp_$(date +\%Y\%m\%d).sql.gz
```

### Upload backups to cloud storage:
```bash
aws s3 cp /backups/campusxp_$(date +%Y%m%d).sql.gz s3://your-backup-bucket/
```

## Step 9 — Deploying to a Server (Basic VPS Setup)

1. **Build the JAR:**
   ```bash
   $env:JAVA_HOME = "C:\Program Files\Java\jdk-21"
   .\mvnw clean package -DskipTests
   ```

2. **Copy to server:**
   ```bash
   scp target/campusxp-0.0.1-SNAPSHOT.jar user@yourserver.com:/opt/campusxp/
   ```

3. **Create a systemd service** (Linux) so it auto-starts:
   ```ini
   # /etc/systemd/system/campusxp.service
   [Unit]
   Description=CampusXP Spring Boot Application
   After=postgresql.service

   [Service]
   User=campusxp
   WorkingDirectory=/opt/campusxp
   Environment="JAVA_HOME=/usr/lib/jvm/java-21-openjdk"
   Environment="DB_URL=jdbc:postgresql://localhost:5432/campusxp"
   Environment="DB_USERNAME=campusxp"
   Environment="DB_PASSWORD=your-strong-password"
   Environment="JWT_SECRET=your-random-secret"
   ExecStart=/usr/lib/jvm/java-21-openjdk/bin/java -jar campusxp-0.0.1-SNAPSHOT.jar --spring.profiles.active=prod
   Restart=on-failure

   [Install]
   WantedBy=multi-user.target
   ```

   ```bash
   sudo systemctl enable campusxp
   sudo systemctl start campusxp
   sudo journalctl -u campusxp -f  # watch logs
   ```
